# ZenoStructures v0.6.1 validation contract

The repaired checkpoint is acceptable as public research evidence only when one exact public source tree passes every gate below.

## Source admission

- The canonical LFRL module path resolves to the strict v0.6.1 implementation.
- Superseded authority-unsafe prototypes are absent from the installable source and test surface.
- Public source contains no owner-private invention/search implementation or internal execution trace.
- Every public file is listed with byte length and SHA-256 in one source manifest.

## Executable gates

```text
Python compileall
complete pytest suite
unified ZenoDEX review-derived falsifier lane
LFRL authority mutation lane
four independent PYTHONHASHSEED replays
public/private publication-boundary checker
FCIS repair source-ratchet checker
clean ZIP checksum and integrity verification
clean ZIP extraction and complete test replay
```

A high aggregate test count cannot replace the named falsifier lane.

## Required semantic mutants

At minimum the gate must kill:

```text
forged debt-discharge receipt
stale current-context receipt
rollback permit crossed to a sibling closed-debt state
rollback permit reused after consumption
```

The release receipt must additionally bind the regenerated inherited-review campaign rather than relabeling the old v0.6 JSON.

## Formal companions

The public packet may include theorem-oriented Lean, Julia, and ESSO inputs. Their presence is not an executed result. A formal receipt must bind exact source, exact toolchain, exact command, complete output, assumptions, and status.

## Clean-source receipt

The final release receipt must identify:

```text
public source-manifest root
public ZIP SHA-256 and byte length
source TAR SHA-256 and byte length
complete test count and clean-replay count
hash-seed replay set
generated campaign inventory
mutants killed and survived
external-tool availability and executed status
explicit nonclaims
```

## Promotion boundary

Passing this contract promotes the checkpoint only to `TESTED_ONLY / RESEARCH_ONLY / UNMOUNTED`. A Rust port requires separate exact-byte vectors, private nominal constructors, no-std checks, Miri, mutation tests, authenticated source mounting, datastore/crash refinement, no-bypass audit, and exact-head review.
