\begin{abstract}
We evaluate exact Boolean truth signatures as an additional source of
equivalence in an e-graph optimizer for ZenoFCIS's finite program representation.
A fixed synthetic corpus contains 100 cases with three to six Boolean inputs
and ordered, sometimes repeated, outputs. A strong local simplifier already
performs factoring, absorption, and structural sharing. Two initial resource
configurations fail because integer extraction reaches solver limits. A smaller,
exploratorily chosen search configuration passes all checks and reduces the
aggregate emitted instruction count from 895 for local simplification to 816,
an 8.8\% reduction. It improves 18 cases across three families, ties 78, and
regresses on four. Compared with otherwise identical rewrite-only egg, semantic
merging saves 38 instructions and improves 12 cases without regressions.
Every candidate is checked over its entire admitted Boolean domain through the
actual evaluator and separate expression and serialized-program interpreters.
A Lean model proves complete-signature and acceptance-gate properties; it does
not verify the implementation. These results support a bounded optimization
case study, with no claim of application runtime speedup or Tau integration.
\end{abstract}

\section{Question and contribution}

Equality saturation retains alternative equivalent programs before choosing an
implementation, reducing dependence on destructive rewrite order
\cite{tate,egg}. Domain semantics can supply equalities that a bounded syntactic
search misses. We ask a narrower engineering question: can complete finite
Boolean signatures improve shared programs in ZenoFCIS beyond a strong local
simplifier and the same e-graph using ordinary rewrites alone?

The contribution is a reproducible, independently checked case study with
explicit failure records and proof boundaries. Truth tables, Boolean circuit
optimization, and semantic e-graphs are established techniques
\cite{bryant,aig,boole,semantic}. We do not introduce a new Boolean-equivalence
algorithm, compare against mature logic synthesis tools, or establish a globally
optimal extracted program.

The experiment uses the pinned \texttt{zeno-fcis/finite-i64/1} program evaluator
\cite{fcis}. It operates offline on a total Boolean fragment containing inputs,
constants, negation, conjunction, disjunction, and conditionals.
No production execution path is changed.

\section{Finite semantics and the acceptance boundary}

Let $\Bool=\{0,1\}$ and $D_n=\Bool^n$, with $0\le n\le6$ for the
implementation. Fix one enumeration $d_0,\ldots,d_{2^n-1}$, where bit $i$ of a
row mask supplies input $v_i$. For a Boolean expression $e$, define
\[
  \sig_n(e)=
    \bigl(\llbracket e\rrbracket(d_0),\ldots,
           \llbracket e\rrbracket(d_{2^n-1})\bigr).
\]
The implementation packs this complete signature into a \texttt{u64};
it uses exact bit-vector equality rather than a probabilistic semantic hash.
Conjunction and disjunction are bitwise operations, and negation is masked to
the admitted rows. Both egg variants compute this analysis as a consistency
check. Only the semantic variant additionally unions classes with equal
signatures.

\begin{proposition}
For total Boolean expressions over the fixed interface,
$\sig_n(e)=\sig_n(f)$ if and only if
$\forall d\in D_n,\ \llbracket e\rrbracket(d)=\llbracket f\rrbracket(d)$.
\end{proposition}
\begin{proof}
Every admitted valuation appears in the same enumeration for both signatures.
Equality of lists therefore gives equality at each valuation, and pointwise
equality gives equality of lists.
\end{proof}

There are $2^n$ valuations and $2^{2^n}$ single-output Boolean functions.
For $m$ ordered Boolean outputs, the number of functions is $2^{m2^n}$.
These finite counts concern a fixed semantic interface. They do not make syntax
finite, bound the number of alternative e-nodes stored during rewriting, or
guarantee a practical search size.

For an actual program $P$, a more suitable observation retains every output
position and every error:
\[
  \obs(P,d)\in \Bool^m+\mathcal E,\qquad
  P\equiv_D Q\ \Longleftrightarrow\
  \forall d\in D,\ \obs(P,d)=\obs(Q,d).
\]
The runtime gate compares ordered output tuples or the actual distinct error,
not merely contract satisfaction or successful-return values. It also checks
that input and output schemas agree. All emitted Boolean programs are admitted
through ZenoFCIS's constructor, which checks types, shape, and references.

A separate protected-selection simulation uses the checked local baseline
$P$ as fallback. Let $\mathrm{ToolChecks}(Q)$ require a positive optimal solver
status and no optimizer failure, panic, or saturation-watchdog timeout.
For a proposal $Q$, define
\[
 A(P,Q)=\mathrm{Valid}(Q)\ \land\ \mathrm{ToolChecks}(Q)\
   \land\ P\equiv_{D_n}Q\ \land\ \cost(Q)<\cost(P).
\]
Its states are
\[
 \mathrm{Baseline}(P)
 \xrightarrow{\mathrm{search}}\mathrm{Proposal}(P,Q)
 \xrightarrow{\mathrm{check}}
 \begin{cases}
   \mathrm{Selected}(Q),&A(P,Q),\\
   \mathrm{Selected}(P),&\neg A(P,Q).
 \end{cases}
\]
Solver failures remain failures of the experiment even when a policy could
fall back. Raw proposal regressions remain visible.

\subsection{Why errors and source identity matter}

ZenoFCIS evaluates all instructions eagerly. Removing an unused overflowing
addition changes an arithmetic error into success. An unselected conditional
arm can likewise overflow before the conditional instruction executes.
The optimizer conservatively excludes arithmetic and comparison nodes,
including dead nodes and conditional arms. Negative controls explicitly reject
these unsafe changes.

Observational equality here does not preserve a program's canonical bytes or
checksum. Changing the instruction DAG can also change resource accounting.
This pilot does not establish equivalence of authoritative state transitions,
events, effects, receipts, budgets, or an imperative shell.

\section{Experimental method}

\subsection{Corpus and local baseline}

The corpus was generated before optimizer results with Python 3.9.6 and seed
\texttt{20261003}. It contains 100 cases, with input arities distributed as
18 cases at three inputs, 29 at four, 27 at five, and 26 at six. There are
76 single-output and 24 multiple-output cases. Output order and duplicate
positions are significant. No case is filtered according to results.
The families and all aggregate outcomes appear in Table~\ref{tab:families}.
The general family uses seeded balanced expression trees of depths three and
four; the other families are constructed identity and sharing patterns.

The deterministic local baseline proposes constant folding, idempotence,
complements, absorption, double negation, associative normalization,
De Morgan identities, conditional simplifications, and common factoring.
A replacement changes all occurrences of a structural subexpression across
all roots. At each step it selects the best strict lexicographic decrease in
\[
   (\text{shared lowered node count},\
     \text{total expression length},\
     \text{ordered expression spellings}).
\]
Proposals do not consult truth tables. Exhaustive enumeration verifies the
result separately. The 1,024-step ceiling is enforced; this corpus needs at
most 12 steps. Identical subexpressions are shared in every variant, including
the raw and local programs.

\subsection{E-graph search and cost}

Both egg variants start from the raw outputs plus the same constants and
declared input leaves. They use the same 33 ordinary rules, scheduler,
resource limits, and shared-DAG integer extractor \cite{extractor}. The rules include factoring,
De Morgan identities, conditional identities, commutation, and reassociation.
Semantic merging adds exact-signature union sweeps during search and before
extraction. Binary egg rules expose generalized factors through bounded
commutative and associative exploration; the local baseline instead considers
flattened factors directly. These are different search policies.

The final representation uses \texttt{Input}, \texttt{Bool}, \texttt{And},
\texttt{Not}, and \texttt{Select}. Disjunction lowers as
\[
  a\lor b=\neg(\neg a\land\neg b).
\]
The extractor assigns cost one to each operator except disjunction, whose
surrogate cost is four. Generated negations can be shared after lowering, so
the additive surrogate differs from final emitted DAG cost. All primary
measurements count actual distinct emitted instructions across every output.
An optimal backend status is optimality reported for the constructed
class-consistent surrogate model, subject to numerical tolerances.
It is not a proof of minimum emitted cost over all equivalent programs.

\subsection{Resource revisions and checks}

The cost criterion was fixed before the first full run: all tool and
verification checks must pass; semantic proposals must have fewer aggregate
instructions than the local baseline, improve at least ten cases, and improve
at least two families. The initial resource configuration fails this criterion.
Table~\ref{tab:configs} records all full configurations. Later resource choices
are exploratory revisions after observing failures; the original registered
configuration is not reported as successful.

The first run has two rewrite-only and ten semantic time-limit failures.
Nine cannot be decoded into selected integer DAGs; three produce behaviorally
correct incumbents that remain rejected for solver status. At 30 seconds, one
semantic extraction still times out. Its 22-node incumbent passes behavior
checks against a 30-node local baseline but is not accepted. The smaller-search
configuration then passes all 200 positive solver-status checks. A
600-second emergency saturation watchdog would also fail a run.

For each successful full configuration, all 400 variants undergo 12,544
complete-domain candidate/input comparisons. Separate Python expression
evaluation, Rust expression evaluation, actual \texttt{Program.evaluate}, and a
Python interpreter for the serialized instruction DAG agree. Another 8,176
invalid-input probes check both wrong-length boundaries and each input position
at $-1$, $2$, and the signed 64-bit extremes. These probes sample the infinite
invalid-input space; they are not its exhaustive enumeration.

Six controls check altered truth functions, a non-Boolean region, unused
arithmetic overflow, unselected-arm overflow, invalid input shape, and invalid
input domain. All pass. Three focused harness tests and seven existing
ZenoFCIS finite-module tests pass. The result analyzer also rejects 13 seeded
receipt defects. A repeat has identical candidate expressions, emitted
programs, signatures, observations, selection decisions, and search snapshot
metadata; timing fields differ.

Semantic proposals use 816 instructions versus 895 for the local baseline:
an 8.8\% aggregate reduction, with 18 wins, 78 ties, and four regressions.
The winning families are absorption/complement, shared guards, and general
balanced expressions. All four regressions add one instruction each. The
protected selection therefore uses 812 instructions, choosing semantic
proposals in 18 cases and the local baseline in 82. The 812-node policy result
is separate from the primary 816-node raw proposal result.

Rewrite-only egg uses 854 instructions, with 13 wins, 80 ties, and seven
regressions against local simplification. Adding semantic unions improves 12
cases, ties 88, and regresses on none relative to rewrite-only egg. Its
38-instruction additional reduction is 4.4\%. This paired comparison supports
an effect from semantic merging under the evaluated configuration.
Much of the overall improvement over local simplification also comes from
ordinary e-graph search.

For example, \texttt{balanced\_general-08} has local outputs
\[
  \bigl(\neg v_3,\
    \neg\operatorname{ite}(v_3,v_2\lor v_3,\neg v_5)\bigr).
\]
When $v_3=1$, the second component is false; when $v_3=0$, it is $v_5$.
Thus the ordered outputs equal
$\bigl(\neg v_3,\neg v_3\land v_5\bigr)$.
The raw, local, rewrite-only, and semantic programs use 26, 10, 7, and four
instructions respectively. The final four are input $v_3$, its negation,
input $v_5$, and their conjunction, with the negation shared between outputs.
The six-input schema remains unchanged and all 64 valuations are checked.
This illustrative case is included in the full aggregates.

aggregate optimizer-speed claim. Separately measured Python baseline search

medians. Different languages and measurement scopes preclude a fair
algorithmic speed ratio. Application execution throughput is not benchmarked.

The largest bounded graphs contain 560 rewrite-only and 1,351 semantic
e-nodes. Semantic unions can expose additional rewrite matches; they do not
guarantee smaller graph storage. The 1,351-node graph also demonstrates batch
overshoot of the configured 1,000-node threshold. Bounded search is not
necessarily full saturation.

\section{Formal checking and relation to Tau}

The accompanying standalone Lean model is replayed with Lean 4.30.0-rc2 and
Mathlib revision \texttt{9977002}. It checks finite valuation and function
counts, equality of complete signatures if and only if pointwise equality,
congruence for total Boolean contexts including conditionals, distributive
factoring, and a candidate-selection theorem. The latter permits an arbitrary
generator and additional acceptance condition while preserving the entire
observation, including an error or every ordered output.

The seven reported theorem closures use only the standard foundations
\texttt{propext}, \texttt{Classical.choice}, and \texttt{Quot.sound}.
There are no proof placeholders, new axiom declarations, or native-decision
escapes. The model's finite enumeration is mathematical and noncomputable;
it is not a refinement proof of the Rust mask loop. Rust semantics, lowering,
e-class maintenance, CBC, solver numerical behavior, and resource or canonical
identity preservation remain outside this formal proof.

Asor describes a broader finite quotient for atomless Boolean-algebra formulas
with fixed finite free-variable and constant scope; quantifier elimination
extends that result to quantified formulas \cite{asor}. This pilot uses only
ordinary finite Boolean inputs. It does not implement that quantified theory,
sentence-valued data, guarded successor, or a Tau decision procedure.
A future Tau application would need an appropriate equivalence oracle and
context-preservation argument. Temporal recurrence additionally requires
appropriate recurrence-state and fixed-point conditions; finite quotients
alone do not imply that every recurrence stabilizes rather than cycles.

\section{Limits and next experiments}

The corpus is synthetic, partly constructed around identities, small, and uses
only one seeded general-tree collection. It does not represent an application
distribution. Resources were revised after observed failures; the result is
exploratory rather than confirmation under an untouched registered protocol.
The benefit is against this local baseline and rewrite set, not ABC, BDD,
Espresso, BoolE, or Nextmap. The cost model counts all instructions uniformly
and does not measure hardware area, application throughput, or protocol-visible
budgets. Solver-reported surrogate optimality cannot eliminate the four
regressions in final emitted cost.

The next useful tests are held-out application guards, comparison with mature
Boolean synthesis, better alignment between extraction and lowered sharing,
and end-to-end verification that includes surrounding eager producers and the
actual resource contract. The present evidence supports smaller, behaviorally
checked Boolean proposals within the stated scope.
