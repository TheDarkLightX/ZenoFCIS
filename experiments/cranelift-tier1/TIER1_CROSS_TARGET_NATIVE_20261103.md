# Tier-1 Cranelift: cross-target and native AArch64 checkpoint (2026-11-03)

**Status:** Real compiler code-size improvement confirmed on x86-64 and AArch64 for exactly one signed-i64 saturating-add CLIF function. New AArch64 native finite validation passed. There is **no qualified runtime speedup**, no upstream-accepted rewrite, and no unqualified VeriISLE proof.

The experiment compares **the same CLIF input** compiled by unchanged and single-rule-patched Cranelift at upstream revision `b1f81d2ad4fc64fbe0e70a7cc5fccac1a7864c49`; the rule is `tier1_i64_signed_saturation_clamp` in the experimental copy of `cranelift/codegen/src/opts/selects.isle`. The ZenoFCIS producer is `85011e3b53c3551cf67f6331af6df3b6b9001825`.

| Target | Compiler optimization mode | Baseline emitted function | Patched emitted function | Saving |
| --- | --- | ---: | ---: | ---: |
| x86-64 | speed | 56 bytes | 39 bytes | 17 bytes (30.4%) |
| x86-64 | speed_and_size | 56 bytes | 39 bytes | 17 bytes (30.4%) |
| AArch64 | speed | 36 bytes / 9 instructions | 32 bytes / 8 instructions | 4 bytes / 1 instruction |
| AArch64 | speed_and_size | 36 bytes / 9 instructions | 32 bytes / 8 instructions | 4 bytes / 1 instruction |

The emitted object bytes are identical between the two opt modes *within each target*, and these are not two independently demonstrated speedups. For x86-64, the 17-byte **symbol** reduction includes literal-pool/padding effects and is not the executed-instruction-byte reduction; the earlier exact-object audit isolated 7 fewer executed bytes. For AArch64, the pinned disassemblies show 9 versus 8 fixed-width instructions, with no relocations.

**Verification boundary:** The pure clamp identity was independently established by a QF_BV/Z3 unsatisfiable counterexample query. The actual named ISLE rule had one VeriISLE applicable pass **only under an experimental locally provided scalar `select` specification**, checked separately against pinned CLIF/interpreter definitions on defined scalar values. These do not establish full poison/undefined, flags/ABI, or generic optimization-chain correctness. The native execution result is finite testing, not an exhaustive `2^128`-pair theorem. No AArch64 latency/throughput/power benefit has been established.
