## Candidate selection
At speed across the five modules, the text-derived static opcode counts include clz 43, clz.i32 3, clz.i64 12 (58 total), rotl 113, select 984, iadd.i64 12291. These are static counts, not dynamic profiles or feature-path reachability. The current x64 inst.isle already implements BMI2 RORX for constant rotates; do not duplicate. Inspecting lower.isle blob 545c79528cbb10fb1280623f23f53880b9762e49 reveals a narrower alternative: generic CLZ without LZCNT uses BSR with zero fallback -1 and subtracts the index from W-1. Change zero fallback to 2W-1 and XOR with W-1. For nonzero, BSR returns i in [0,W-1], and (W-1) XOR i = W-1-i for W=32,64. For zero, CMOVZ discards the architecturally undefined BSR destination and selects 2W-1, whose XOR with W-1 equals W. Flags must be dead after the returned value; CMOVZ must consume BSR ZF before XOR. No poison/traps from CLZ itself.

A local independent bounded post-BSR screen enumerated 40,960 tuples (W in {32,64}, sentinel and constant in [0,2W), xor or subtract-from-constant) and found precisely the two XOR candidates. This is exhaustive for that abstract palette only; the baseline -1 sentinel is outside that bounded sentinel range. Actual GNU-assembled SysV native test kernels returned the right value in 400,584 calls (baseline and candidate combined; boundary and seeded random tests), zero mismatches. Handwritten baseline 21/29 bytes and candidate 15/20 bytes for 32/64-bit respectively. These numbers include fixed ABI return and are not compiler output or a fair claim of optimal baseline code size. No throughput result. ZenoFCIS's registered machine target encoder does not contain BSR; this screen is not a new ZenoFCIS machine proof. Use conditional abstract equivalence and independently test emitted objects next.

Decision: defer scalar bitselect as an upstream proposal unless maintainer identifies a relevant non-Wasm consumer or new corpus reachability. Prioritize CLZ fallback A/B, subject to actual compiler code size and feature path frequency, keeping baseline and candidate LZCNT-enabled controls. No speculative upstream PR. No user action required.
