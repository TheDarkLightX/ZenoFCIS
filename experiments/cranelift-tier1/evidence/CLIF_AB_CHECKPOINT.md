## Independently corroborated facts

The baseline scalar saturating-add CLIF function emits **56 bytes** of ELF function-symbol extent versus **39 bytes** for the hand-written equivalent shift/add formulation: **17 fewer symbol bytes** (a roughly 30.4% reduction in this one benchmark). These are **not** the previously reported 31→22 standalone raw-byte kernels. The baseline symbol includes **10 bytes after its first and only `ret`** (constant-pool data/padding); the straight-line instruction prefix through `ret` is **46 bytes** versus **39 bytes**, a **7-byte executed-code-prefix difference**. This prefix metric is valid only for these specific single-block, no-branch fixtures; it must not be used as a general arbitrary-function cost estimator. Disassemblers may misinterpret the baseline's embedded data after `ret` as instructions.

Fresh Z3 **4.15.4**, QF_BV, returned `unsat` for the candidate-vs-baseline **pure signed-i64 saturating result** inequality over all `2^128` input pairs under the modeled expressions. It also ran 10,100 deterministic independent integer reference checks; the pinned `clif-util test` filetests passed. This does not prove C/CLIF poison semantics or the complete x86 ABI. The raw native Zeno profile separately passed its seven envelope tests, Z3 checker, bounded search, deduplicated catalog, emission/replay and 20,289 native tests for each existing raw kernel.

As an extra **independent local recheck** of the actual Cranelift-emitted object files, both ELF objects were extracted from the uploaded CI artifact, had their function symbols renamed only with `objcopy`, and were dynamically linked with GCC. Each was called through `ctypes` on **250,361** signed-input pairs (19×19 boundary grid and 250,000 seeded pseudorandom pairs) against an unbounded Python integer saturating-add oracle, with **no mismatches**. The original object SHA-256 values in `qualified_clif_ab.json` were checked before symbol renaming. This is finite execution, not formal whole-object verification or a throughput benchmark.

The [structured, reusable A/B receipt](qualified_clif_ab.json) retains native symbol costs, code/data-tail distinction, source and ELF digests, solver/result pins, original CI artifact location and explicit nonclaims. It is a source-specific **CLIF formulation comparison**, **not an implemented Cranelift rewrite**. There is no upstream Wasmtime PR or claim that its optimizer will automatically choose the shorter form. A safe upstream change still requires a concrete generalizable rewrite/lowering, its own verification including flags and undefined/poison concerns, and a fresh same-configuration baseline/patch comparison, preferably also representative workload benchmarks.

## Reproduction and audit

Re-run `.github/workflows/tier1-cranelift-satadd.yml` at the exact experimental source commit, or follow the commands in `experiments/cranelift-tier1/README.md`. On the published A/B objects, `nm -S --defined-only --format=posix`, `objdump -d -Mintel` and `sha256sum` reproduce symbol-byte and identity evidence. Never recompute binary hashes after `objcopy` and mistake those for the original emitted objects.

Do not merge this experiment into main or submit the CLIF-only difference as an upstream ISLE patch.
