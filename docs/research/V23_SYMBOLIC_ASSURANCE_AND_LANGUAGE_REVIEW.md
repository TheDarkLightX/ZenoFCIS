Definition of done for this review: identify actual supported guarantees and missing proof links; distinguish language interoperability from verified code generation; propose a small ordered V2.3 scope with testable completion criteria. **The forgotten symbolic gap is a chain of four obligations, not a solver setting.**

`reviewed behavior → admitted runtime IR → exact counterexample query → checked UNSAT certificate → property of the actual execution target`

A certificate can establish UNSAT of the wrong query. A correct encoding can still rely on an unchecked solver answer. A theorem about compiled IR can miss the owner's intended rules. Correct Rust-source semantics alone do not prove emitted Go/Python/JS code or a compiler's binary. V2.3 must name and bind every link it claims.

What stronger proof work should deliver

| Obligation | Small implementable first deliverable | Acceptance criterion |
| --- | --- | --- |
| A. Exact certificate checking | One documented certificate format/logic fragment and one named, pinned checker/kernel; retain the query and certificate separately. Start with Boolean/linear-integer obligations already expressible by the scalar IR. | Independently check every inference for the exact query. Wrong-query, corrupt/truncated proof, missing premise, unsupported rule, timeout and resource-only failures refuse. Dual UNSAT alone never passes. |
| B. Encoding/refinement | Move a small supported encoder behind an explicit mathematical relation to `execute_v2`; prove AST semantics and text serialization preserve that relation. | At minimum prove `actual admitted counterexample ⇒ satisfying assignment of emitted query`; then checked UNSAT rules out every actual counterexample. Include eager dead/unselected-node traps, overflow, output domains, typed guards and case coverage. Prove meter omission is conservative, or encode it. |
| C. Contract/rules-to-IR meaning | Freeze an independent rule semantics and the owner's required accept/reject examples, then link admitted descriptors to that meaning. A bounded instance correspondence checker is a useful first result; label it accordingly. | Catch altered rule priority/default, deleted effects, wrong field/variant mapping and a generator that shares its own bug with expected outputs. Preserve initial state, reasons, class, complete post-state/effects and declared observations. IR admission alone is insufficient. |
| D. Emitted source/binary connection | Keep the same Rust core for bindings; retain exhaustive artifact conformance for emitters. Add source-level emitter refinement only for a declared subset when needed. | Bind program, emitter, source, compiler/runtime, executable and ABI. Execute every admitted finite input where claimed. State compiler, runtime, host transport and deployment assumptions explicitly; a source theorem is not verified compilation. |

The first certified symbolic milestone should be a large-domain scalar equivalence/property that crosses the current enumeration cap, with one positive certificate and planted semantic/encoding/certificate/binding defects all refused. Keep unsupported nonlinear arithmetic, richer values and temporal properties outside this first fragment. No symbolic receipt may authorize adoption until A+B and the exact subject/domain/observations binding are checked; claims about owner intent additionally need C, and foreign execution needs D. Introduce a versioned checked-evidence route, not a relabeling of existing `attested` files.

Proof-engineering hygiene: freeze the requested theorem, definitions and allowed assumptions separately from a proposed proof. For optimization permit a different implementation only under a fixed equivalence/refinement theorem. Carry source/IR/parameter/genesis/query/certificate/checker identities together. Record vacuity, achievable success and environmental assumptions separately from safety.

For expansion, prefer one additional host SDK over the actual Rust boundary first (for example a Go consumer using versioned subprocess messages/canonical bytes). This expands usability without inventing another authoritative evaluator. Then choose one native emitter only if a real consumer needs standalone target execution; keep its conformance and proof claims separate.
A future C ABI must specify canonical encoding, widths/endianness, lengths, ownership/lifetimes, aliasing, versioning, error classes, panic/trap handling and resource limits; never expose a forgeable publication handle. A Wasm binding should preserve that semantic contract, admit its exact import/export set, retain bounded private memory/instance state and test host call ordering. Bindings require codec/transport refinement; separately generated implementations additionally require emitter/runtime refinement. Neither route inherits proof from a hash alone.

Reusable core standard library

G1 already sketches reservation/rate-limit/quorum families, but its universal parameter proofs are not supplied by a verified generic evaluator. The current policy whitelist has no family/import/compose fields ([crates/zeno-fcis-cli/src/contract/rules.rs:225](../../crates/zeno-fcis-cli/src/contract/rules.rs#L225)). The native composed-program crate is explicitly retired ([crates/zeno-fcis-composed-program/src/lib.rs:1](../../crates/zeno-fcis-composed-program/src/lib.rs#L1)); `zeno-fcis-compose` checks evidence/footprint bindings but expressly trusts an external `EvidenceVerifier` ([crates/zeno-fcis-compose/src/lib.rs:1](../../crates/zeno-fcis-compose/src/lib.rs#L1)). These are design material, not an already proved composable standard library.
Use checked data declarations through `zeno_fcis::program`, not a revived callback-authority API. Begin with the small Bool/i64 catalog proposed in the companion core-library review: bounded counters/budgets/reservations, approval/quorum, CAS/version checks, idempotency, retry/FSM/deadline/epoch quota. Catalog breadth can grow after one repeatable qualification contract works.
Each entry needs exact parameter bounds, state/command/context schemas, genesis, positive behavior requirements, invariant/rejection/effect semantics, resource policy, canonical identities, migration compatibility, and evidence at the correct scope. Time and authorization remain explicit supplied facts with named environment responsibilities.
Use orthogonal fields for method, supported domain, assumptions, runtime binding and authority: examples tested; exhaustive instance checked; solver-attested family property; kernel-checked formula; implementation-refined property; separately checked shell lifecycle. A parameter instance test is not a theorem for all parameters; a certificate for a formula is not runtime refinement.
Start composition with two components in one deterministic combined descriptor and one existing atomic shell commit. Require disjoint ownership or an explicit merge law, producer guarantee implying consumer assumption, exact version/parameter/root binding, all required component occurrences, summed resource bounds and precise Reject/CommittedFailure effects. Prove a coupled invariant that neither local proof establishes alone. Sequential order, branch coverage, duplicate effects/nonces and budget failure are observable. Defer parallel/distributed composition until noninterference/commutation and crash/retry semantics are separately established.

ZAL: improve the existing workflow before widening the language

The published addon already has controlled English/symbolic round trips, explanations, traces, semantic witnesses, seven MCP tools, separate human review, checker/revision binding and reviewed export. [docs/zal/HARNESS_INTEGRATION.md:5](https://github.com/TheDarkLightX/ZenoFCIS/blob/7eafb5c6524d1b2ba76e9437cb534b5234b1b106/docs/zal/HARNESS_INTEGRATION.md#L5), [integrations/zal/workflow.py:127](https://github.com/TheDarkLightX/ZenoFCIS/blob/7eafb5c6524d1b2ba76e9437cb534b5234b1b106/integrations/zal/workflow.py#L127), [integrations/zal/mcp.py:19](https://github.com/TheDarkLightX/ZenoFCIS/blob/7eafb5c6524d1b2ba76e9437cb534b5234b1b106/integrations/zal/mcp.py#L19). Rebuilding another editor or review protocol is unnecessary.
Its actual profile is 1–8 states, 1–8 events, 0–4 fresh Boolean facts, at most 1,024 raw tuples; BFS covers the full finite reachable graph, whereas interactive traces cap at 64. No arithmetic, effects, liveness/fairness or concurrency semantics are supplied. The Python checker and lowering are tested, not machine-proved. Factory correspondence compares class/reason/successor/empty deliveries, not usage or publication identity ([docs/zal/SPECIFICATION.md:67](https://github.com/TheDarkLightX/ZenoFCIS/blob/7eafb5c6524d1b2ba76e9437cb534b5234b1b106/docs/zal/SPECIFICATION.md#L67), [integrations/zal/factory.py:20](https://github.com/TheDarkLightX/ZenoFCIS/blob/7eafb5c6524d1b2ba76e9437cb534b5234b1b106/integrations/zal/factory.py#L20)).
The seed has no application invariants; replacing `authorized` with `true` can pass consistency while changing a rejection to acceptance. Make this visible in the primary workflow. State-only invariants cannot encode every transition requirement; gather independent owner examples and keep missing requirement semantics explicit, rather than interpreting a green consistency check as authorization safety.
Keep separate displays for “meaning reviewed,” “finite checks complete,” “solver attested,” “certificate checked,” and “factory realization tested.” Lead with a readable witness and plain-language consequence; expose full hashes/assumptions on demand. Preserve exact stale-review refusal underneath convenience controls.
Current shared-file agreement is cooperative same-user state, not authenticated reviewer approval. No MCP acceptance tool exists. If 2.3 makes approval a security claim, reviewer credentials/store must be outside the coding agent's write authority; otherwise keep the present limitation explicit. Browser DOM-double tests and configuration inspection do not substitute for native keyboard/focus/touch/accessibility or an actual permitted MCP exchange.

Ordered small V2.3 milestones and acceptance

1. **Freeze the capability/evidence contract after V2.2.** Record the actual baseline, reconcile the retired Lean path and historical ZAL/G1 wording, and publish machine-readable supported profiles, observations, tools and open gates. Acceptance: every advertised proof route has a real exact-source positive and semantic negative; unsupported modes remain explicit refusals.
2. **Ship ZAL workflow polish over its existing profile.** One user can inspect a rule, ask why, detect a planted unauthorized-approval change, inspect its distinguishing input, review the exact candidate and verify export without hand-editing JSON/digests. Acceptance: preserved drafts/selection, stale/concurrent proposal refusal, no agent acceptance path, native browser/accessibility and real SDK/harness checks reported distinctly; factory correspondence still passes.
3. **Qualify three seed cores and a reusable registry.** Begin with a counter/budget, reservation and approval/FSM family under existing limits; expand toward the companion ten-core catalog only after the same contract is reusable. Acceptance: independent requirements/negative examples, exact parameter-bound instances, complete finite replay, source/claim/genesis binding, and an explicit evidence class for every property. No claim of universal parameter proof from sampled instances.
4. **Close symbolic A+B for one fragment; stage C explicitly.** One above-cap scalar example gets an independently checked certificate and the proved query/runtime connection. Acceptance: unsupported syntax/logic and every planted encoding/certificate/subject failure refuse; bound budgets and evidence custody hold; the retained SAT replay and old Attested route remain honest. Add a rules-to-descriptor refinement/instance checker before claiming application-source semantics.
5. **Prove one useful composition, then expose it.** Compose two seed cores for reservation plus approval/spending, with a shared resource invariant and one atomic publication. Acceptance: missing/reordered/duplicate component, contradictory assumptions, overlapping writes, wrong parameters, budget refusal and duplicate-effect witnesses are rejected; actual generated app replay agrees. Larger catalog/parallel composition follows this demonstrated pattern.
6. **Deliver one additional language consumer.** Use the same canonical ABI and actual Rust execution; verify exact bytes/errors, extreme integers, malformed inputs, bounded resources and replay across both languages. Acceptance: source/package/ABI version binding and zero host authority bypass. An optional new emitter has its own full-domain conformance/purity/refinement gate and must not be marketed as a proved compiler.

Keep these on a separate V2.3 plan/branch. Current V2.2 package/control/full-product work must finish under its existing scope. The architectural recommendation is to keep one execution core, small independently checked proof links and honest per-component/per-language guarantees; implementation still needs independent source review and exact-tree qualification.
