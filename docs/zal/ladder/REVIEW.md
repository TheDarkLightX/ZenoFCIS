# Review ladder interpretations

Use this checklist to compare the rendered requirement with the intended
behavior. Passing parser and fixture checks does not replace interpretation
review or supply runtime authority.

- Read the scope strip on each selected rung: theory, source, projection,
  event order, mode, horizon, assumptions, definitions and evidence status.
- Check vacuous cases. Material implication permits a false premise; universal
  quantification over an empty object domain is true. Require legitimate
  scenarios and a reject-everything control separately.
- Read every prime as “after this event”, and next as another recorded event.
  Check now-witnesses, finite endpoints, until's required right witness and
  deadline equality. Within k includes the present event and k further events.
- Confirm that grouped compound counts and nested Boolean formulas retain
  their intended scope.
- Open every shortened name and registered full-property reading. The short
  alarm phrase includes its entire request domain and assumptions; it creates
  no permission to disable exit.
- For vault loss, specify assets, valuation, legitimate credits and independently
  justified entitlement discharges. Include partial drains and initial loss.
- For withdrawals, choose eventual progress, an event bound or a separately
  defined wall-clock requirement. Match the same frozen request identity and
  keep legitimacy fixed at submission. Weak fairness gives no finite bound.
- For UI discovery, specify required actions, presentation/input modes, focus
  and modal navigation rules, and a navigation bound. Discovery and execution
  permission are different requirements.

The sample temporal definitions are visibly marked PLACEHOLDER and OPEN.
No default policy number or wording is represented as owner-approved.
